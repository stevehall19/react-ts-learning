**The race E1 found.** The first e2e run failed with HTTP 500: Playwright's two quick increment clicks ran concurrently, both read the row, and MariaDB 11.8 (`REPEATABLE-READ` with `innodb_snapshot_isolation=ON`) rejected the second update with error 1020 ("Record has changed since last read"). Other databases would have lost an increment silently. The learner reproduced it with `concurrentIncrementsAreNotLost` (20 increments on 10 threads via `invokeAll`, red first), then fixed it with a pessimistic lock: `findByIdForUpdate` (`@Lock(PESSIMISTIC_WRITE)`, i.e. `SELECT … FOR UPDATE`) used by `increment` and `reset` through `CounterService.findForUpdate`. Optimistic locking (409s) and an atomic `UPDATE` were discussed and rejected.

**A10, idempotency.** Started from the learner's question "what's the best way to handle idempotency with Spring Boot?". Claude scaffolded the aspect, annotation, migration and exception (checked against a reference solution first); the learner wrote the tests (red first), the controller changes, the handlers, the cleanup job, the repository refactor and the OpenAPI docs. How it works: the client sends an optional `Idempotency-Key`; `IdempotencyAspect` runs one transaction that `INSERT`s the key (`IdempotencyKeyRepository.claim`), proceeds, and stores the status, `Location` and body. A concurrent same-key request blocks on the primary key until that commits, then gets `DuplicateKeyException` and replays the stored response (`Idempotent-Replayed: true`). The same key with a different request hash gets 422. A failure rolls the key back with everything else, so errors aren't cached. Endpoints must return `ResponseEntity` (the aspect casts). Only create and increment are `@Idempotent`; reset and delete are naturally idempotent. Design choices the learner accepted: `JdbcClient` rather than JPA for the key table (immediate `INSERT`, specific `DuplicateKeyException`, set-based `DELETE`), a repository but no separate service yet, an optional header, and keys kept at least 24 hours by an hourly job (`IdempotencyKeyCleanup`, which logs the count).

## Environment gotchas

- **PowerShell 5.1:** mangles `"` nested inside arguments to native programs (SQL, JSON); pipe the text on stdin instead (`… | kubectl exec -i …`, `… | curl.exe --data-binary '@-' …`). `curl` is an alias for `Invoke-WebRequest`; use `curl.exe`.
- **Line endings:** IntelliJ created some files with CRLF; Prettier then fails `npm run check`. `npm run format` fixes it; set IntelliJ's default line separator to LF. That setting only affects **new** files: IntelliJ keeps an existing file's separator (change one from the status bar, bottom right, or a whole folder with File → File Properties → Line Separators). Prettier ignores `backend/`, so CRLF in Java files isn't caught; `.gitattributes` (`* text=auto eol=lf`) normalizes on commit, and `git ls-files --eol` shows the working copy (`w/crlf`) versus the index.
- **`mvnw` executable bit:** Windows commits it as `100644`; it needed `git update-index --chmod=+x` for the Linux runner.
- **IntelliJ auto-imports:** watch for the wrong `assertEquals`/`fail` (Spring, AssertJ) and stray static imports like `AbstractPersistable_.id`.
- **MariaDB date arithmetic:** `NOW() - ?` with a number does integer arithmetic on `20261007163955`-style values and silently compares wrongly; always write `NOW() - INTERVAL ? SECOND`.
- **MariaDB DDL:** `ALTER COLUMN` only sets or drops a default; change nullability by restating the column with `MODIFY COLUMN x … NOT NULL` (`SET NOT NULL` is PostgreSQL). Adding a `NOT NULL` column without a default to a table with rows silently fills them with `''`, so backfill or delete first. DDL commits immediately, so a migration that fails halfway leaves its earlier statements applied. Test a migration on a throwaway container (`docker run --rm mirror.gcr.io/library/mariadb:11.8`, then pipe V1…Vn through `mariadb`) before it reaches the cluster.
- **`JdbcClient.param(String, Object)`** is the named-parameter overload: `.param(key, ownerId)` with a `String` key binds a parameter named after the key's value. Use `.params(a, b)` for positional `?`s.
- **Mock JWTs:** plain `jwt()` always has subject `"user"` and token value `"token"`, so tests that should differ by user or by token need `.jwt(j -> j.subject(…))` or `.tokenValue(…)`. A Mockito stub for one subject with a request sent as another returns `null`, which shows up as a 500 from the catch-all handler.
- **Tree-shaking and module side effects:** a static `import` always runs the imported module. A module that only declares functions can be dropped when unused; one that does work at load (`new UserManager(…)`, a `throw`) stays in every build. Vite replaces a missing `import.meta.env.X` with `undefined`, so a guard like `if (!x) throw` becomes an unconditional `throw` in builds without the variable. Check the Pages build with `GITHUB_PAGES=true npx vite build --outDir <tmp>` and search the bundle.
- **React rules TypeScript doesn't check:** `tsc` accepts `async` components (React 19's types allow them for server components) and module-level hook calls; oxlint's `react-hooks/rules-of-hooks` catches the first, and React throws at runtime for both. An uncaught render error with no error boundary leaves an empty `#root` (a blank page); read the browser console.
- **Git Bash on Windows:** `openssl base64` ends its output with `
` (strip `
` too), and Python's `open(…, 'w')` writes CRLF unless `newline='
'` is passed. Vite run on a path with the short name `ADMINI~1` rejects its own `index.html`; use the long path.
- **Playwright and Keycloak sessions:** `storageState` saves cookies and `localStorage`, not `sessionStorage` or in-memory state; with tokens in memory, what makes the tests signed in is Keycloak's session cookie. Never commit `playwright/.auth`.
- **PowerShell 5.1 `ConvertFrom-Json`** outputs a JSON array as one object, so `@($json | ConvertFrom-Json).Count` is 1 for `[]`; unroll with `| ForEach-Object { $_ }`.
- **Spring test context failures:** if one `@SpringBootTest` class can't start the context, later classes only report `ApplicationContext failure threshold (1) exceeded`; the real cause is the first `Caused by` in the first failing class. Two `@ExceptionHandler`s for the same exception are one such cause (`Ambiguous @ExceptionHandler method`).
- **IntelliJ test runs** don't write surefire reports; ask the learner to paste the results, or run `.\mvnw test` and read `target/surefire-reports`.
- **Flyway on MariaDB:** a failed migration leaves a `success = 0` row; drop `counter` and `flyway_schema_history` (or `flyway repair`) before retrying. Never edit an applied migration.
- **MariaDB passwords:** only applied on first init of the PVC; `helm upgrade` won't change them.
- **Jib images in the cluster:** `jib:dockerBuild` loads into Docker Desktop's engine, which the kubeadm cluster uses directly. A rebuild with the same tag needs `kubectl rollout restart deployment counters-api`. Port 8080 is held by `wslrelay` (the cluster's LoadBalancer) while the API pod runs, so `spring-boot:run` can't start at the same time.
- **Spring Boot 4.1 probes:** liveness/readiness groups are on by default even outside Kubernetes; `management.endpoint.health.probes.enabled` (top-level `management:`, not under `spring:`) is set anyway for clarity.
- **`helm create` scaffolds:** removing values the templates still read (`autoscaling.enabled`) gives a nil-pointer render error; `with` blocks tolerate missing values, `if not .Values.x.y` doesn't. `helm lint` doesn't validate fields; use `helm template … | kubectl apply --dry-run=server -f -`.
- **kind vs Docker Desktop:** kind can't see the runner's Docker images until `kind load docker-image`, and its LoadBalancer services stay `<pending>`, hence the port-forward. Use `kubectl rollout status` rather than `helm install --wait`, which may wait on the LoadBalancer address.
- **Stuck GitHub runs:** a run can sit in `queued` with no jobs; cancel and force-cancel return 409, delete returns 403. Leave it (GitHub expires it), and start a fresh run with `gh workflow run e2e.yml` or an empty commit.
- **Prettier checks `.github/`:** it rewrites `[ main ]` to `[main]`; run `npm run check` before committing workflow changes.
- **Local e2e and seed data:** the seeded-counters test fails if a seeded counter was deleted from the long-lived local database; re-add it. CI's database is always fresh.
- **Spring not running:** the dev app shows "Couldn't load counters: HTTP 502" (Vite proxy's plain-text 502). In dev, React Strict Mode makes two `GET /api/counters` requests on load; that's expected.
- **Browser pane:** has its own localStorage and can drive `localhost` dev servers; useful for importing `/src/countersApi.ts` in the console to exercise the client.
